# DevSpace 本机助手

让 ChatGPT 在你授权的范围内处理电脑文件、调用本机工具、委派开发，并在确认后应用修改。每个人自行安装、登录和管理自己的连接；没有由作者集中运营的中转服务。

作者：Nar / 那不然。基于 [DevSpace](https://github.com/Waishnav/devspace) 的独立 macOS 配套项目，保留上游 MIT 声明。

## 当前版本：0.4.4 源码发行

这次发行统一收录现有功能代码与测试。**它仍是已有 DevSpace 部署的集成源码，不是新电脑一键安装包。** 新机安装向导和干净环境验收仍需完成，不能把下载成功或测试通过当成已经接入 ChatGPT。

| 能力 | 当前范围 |
| --- | --- |
| 文件夹授权 | 本机选择目录、只读/读写、撤销和恢复 |
| 本机工具 | 受控 CLI 发现、执行、状态和取消，按各自账号配置 |
| Codex/Grok 开发 | 隔离副本、凭据留在父进程、封存产物与续接 |
| Grok X 搜索 | 独立只读官方 X Search；开发模式不带搜索 |
| 依赖与验证 | npm 官方锁定依赖；测试、构建、短暂本机启动检查 |
| 应用与撤回 | 展示具体版本、用户确认、源文件变化拒写、备份和撤回 |
| show_changes | 最近工作区检查点后的净改动；不是 Git 历史 |
| 内容发布 | Blog/公众号适配器源码；需自备发布脚本、账号与站点配置 |
| 历史同步 | 可选本机导出及加密设备间同步；默认不共享真实记录 |

## 下载和检查源码

从 Releases 下载源码包，或克隆本仓库。Node 24 环境执行：

```sh
npm ci --ignore-scripts
npm run check:public
npm test
npm run test:context
```

macOS 测试包含真实系统沙箱。Linux CI 仅核验可移植逻辑，**不代表支持 Linux 部署**。当前执行隔离面向 macOS Apple Silicon。

## 已有安装怎么升级

先阅读 [集成条件](docs/integration.md) 和 [运行配置](docs/configuration.md)，核对自己现有的目录、服务标签、上游版本、启动器及账号位置。不要直接对任意电脑运行安装脚本。

能力组件更新使用 `node scripts/install-capabilities.mjs --apply`；新增能力必须显式开启，见配置文档。更新会检查任务是否忙碌、备份和重启；失败尝试恢复。它不替代首次部署，不自动取得系统授权。

## ChatGPT 怎么连接

每台电脑使用自己的稳定 HTTPS MCP 地址和身份验证。程序本身绑定本机地址，通过使用者自行配置的连接方式供 ChatGPT 访问；不要暴露无认证的本地服务。然后在自己的 ChatGPT 支持的自定义连接入口添加地址并完成授权。账号入口、系统权限和首次登录需要本人操作。

工具清单可能缓存，打开工作区会返回兼容调用说明。验证必须在 ChatGPT 网页发起新任务，不能仅用开发环境直接调用代替。

## 已验证与限制

46 项 Node 回归覆盖权限、撤权、依赖来源限制、应用/撤回、源文件变化、Grok令牌刷新和工作区差异。网页实测完成新开发任务→独立安装/测试/构建/启动→预览→应用→读文件→撤回。show_changes 的缺失问题已修复，并验证新增文件可见、删除后净改动为空。

这些证据来自开发用 Mac；公开配置的其他机器仍要单独验收。沙箱不是虚拟机，不承诺严格总磁盘/进程配额。多文件应用不是整批原子事务，中断会保留恢复记录，不能盲目重试。私有依赖、本地依赖、多工作区、安装脚本、长期预览、浏览器点击、桌面操作及 PR 尚未完整接入。

通过工具返回的文件内容会进入 ChatGPT；“文件存本机”不等于“内容绝不离开本机”。仓库不包含作者账号、真实会话或服务密钥。升级由电脑主人决定。

## 开发与发行

本仓库作为后续统一代码来源。开发分支验证后合并，打标签生成固定发行包；常驻主机只安装已验证版本，不随开发分支即时更新。各电脑的配置、账号、数据和日志留在本机。

先修复失败项，再网页复测，再发行，再更新常驻主机。新机安装包必须单独通过干净环境安装验收后才会标为可用。
